# Chapter 4: Spring Data JPA (Complete Interview Notes)

# 4.1 What is Spring Data JPA?

Spring Data JPA is a Spring module built on top of JPA that reduces boilerplate code for database operations.

Instead of writing EntityManager code manually, Spring Data JPA provides Repository interfaces and automatically generates implementations.

---

## Without Spring Data JPA

```java
@Service
public class EmployeeService {

    @PersistenceContext
    private EntityManager entityManager;

    public Employee save(Employee employee){
        entityManager.persist(employee);
        return employee;
    }
}
```

Lots of boilerplate code.

---

## With Spring Data JPA

```java
public interface EmployeeRepository
        extends JpaRepository<Employee, Long> {
}
```

```java
employeeRepository.save(employee);
```

Spring generates the implementation automatically.

---

## Definition

Spring Data JPA is a Spring framework module built on top of JPA that simplifies database access by providing:

* Repository abstraction
* Automatic query generation
* Pagination
* Sorting
* Custom queries
* CRUD operations

# 4.3 Repository Pattern

Before Spring Data JPA:

```java
public class EmployeeDAO {

    public Employee save(Employee employee){}

    public Employee findById(Long id){}

    public void delete(Long id){}
}
```

Every project repeated this code.

Spring Data JPA solves this using Repository interfaces.

---

## Repository Pattern Definition

Repository Pattern separates:

```text
Business Logic
        FROM
Database Logic
```

Benefits:

* Cleaner code
* Reusable
* Easier testing
* Less boilerplate

# 2. CrudRepository

Adds CRUD operations.

```java

```

Methods:

```java

findById()

findAll()

delete()

deleteById()

existsById()

count()
```

---

# Example

```java
public interface ProductRepository
extends CrudRepository<Product, Long> {
}
```

Available:

```java

findById()

findAll()

delete()
```

---

# 3. PagingAndSortingRepository

Extends CrudRepository.

Adds:

```java
findAll(Pageable pageable)

findAll(Sort sort)
```

---

## Example

```java
Pageable pageable =
PageRequest.of(0,10);

repository.findAll(pageable);
```

Returns:

```text
First 10 Records
```

---

# Why Needed?

Suppose table has:

```text
10 Million Rows
```

Bad:

```java
findAll();
```

Good:

```java
findAll(pageable);
```

# 4.5 Internal Spring Data JPA Architecture

Most Important Interview Topic

---

# What Happens When We Create Repository?

You write:

```java
public interface ProductRepository
extends JpaRepository<Product, Long> {
}
```

Notice:

```text
No save() implementation
No findById() implementation
```

Still it works.

Why?

Because Spring creates a Proxy Object.

---

# What is a Proxy Object?

A Proxy is a middleman object generated at runtime.

Think:

```text
Customer
   ↓
Receptionist
   ↓
Manager
```

Receptionist = Proxy

The customer never directly talks to the manager.

---

# Repository Proxy Flow

```text
ProductRepository
       ↓
Dynamic Proxy
       ↓
SimpleJpaRepository
       ↓
EntityManager
       ↓
Hibernate
       ↓
Database
```

---

# Startup Flow

Application Starts

```text
Spring Boot Starts
        ↓
Scans Repository Interfaces
        ↓
Finds ProductRepository
        ↓
Creates Dynamic Proxy
        ↓
Proxy Stores Reference To
SimpleJpaRepository
        ↓
Application Ready
```

---

# Runtime Flow

You call:

```java
productRepository.save(product);
```

Actual Execution:

```text
ProductRepository
        ↓
Proxy Object
        ↓
SimpleJpaRepository.save()
        ↓
EntityManager
        ↓
Hibernate
        ↓
Database
```

# 4.7 Query Derivation

One of the biggest features of Spring Data JPA.

---

You write:

```java
findByTitle(String title)
```

Spring automatically generates:

```sql
SELECT *
FROM product
WHERE title=?
```

No SQL written manually.

---

Runtime-generated object created by Spring that intercepts repository calls and delegates them to SimpleJpaRepository.
