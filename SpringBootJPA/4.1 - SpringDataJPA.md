# Chapter 4: Spring Data JPA (Complete Interview Notes)

# 4.1 What is Spring Data JPA?

Spring Data JPA is a Spring module built on top of JPA that reduces boilerplate code for database operations.

Instead of writing EntityManager code manually, Spring Data JPA provides Repository interfaces and automatically generates implementations.

---

## Without Spring Data JPA

```java
@Service
public class EmployeeService {

    @PersistenceContext
    private EntityManager entityManager;

    public Employee save(Employee employee){
        entityManager.persist(employee);
        return employee;
    }
}
```

Lots of boilerplate code.

---

## With Spring Data JPA

```java
public interface EmployeeRepository
        extends JpaRepository<Employee, Long> {
}
```

```java
employeeRepository.save(employee);
```

Spring generates the implementation automatically.

---

## Definition

Spring Data JPA is a Spring framework module built on top of JPA that simplifies database access by providing:

* Repository abstraction
* Automatic query generation
* Pagination
* Sorting
* Custom queries
* CRUD operations

Before Spring Data JPA:

```java

    public Employee save(Employee employee){}

    public Employee findById(Long id){}

    public void delete(Long id){}
```

Every project repeated this code.

Repository Pattern separates:


* Cleaner code
* Reusable
* Easier testing

# What Happens When We Create Repository?

You write:

```java
public interface ProductRepository
extends JpaRepository<Product, Long> {
}
```

Notice:

```text
No save() implementation
No findById() implementation
```

Still it works.

Why?

Because Spring creates a Proxy Object.

---

# What is a Proxy Object?

A Proxy is a middleman object generated at runtime.

Think:

```text
Customer
   ↓
Receptionist
   ↓
Manager
```

Receptionist = Proxy

The customer never directly talks to the manager.

---

```text
       ↓
```

Chapter 5: Repository Pattern in Spring Data JPA
Spring Data JPA provides a hierarchy of Repository interfaces that progressively add more functionality.

5.1 Repository Hierarchy
Repository  <--  CrudRepository  <--  PagingAndSortingRepository  <--  JpaRepository

Interface
What It Provides
Repository<T, ID>
Marker interface — no methods. Base of the hierarchy.
CrudRepository<T, ID>
save(), findById(), findAll(), delete(), count(), existsById()
PagingAndSortingRepository<T, ID>
findAll(Sort), findAll(Pageable)
JpaRepository<T, ID>
flush(), saveAndFlush(), deleteInBatch(), getOne() + all above


5.2 Creating a Repository
@Repository
public interface StudentRepository extends JpaRepository<Student, Long> {
    // Spring Data JPA auto-implements this interface
}

Just by extending JpaRepository, you get these methods for free:
save(entity) — INSERT or UPDATE
findById(id) — SELECT by primary key, returns Optional<T>
findAll() — SELECT all records
findAll(Sort sort) — SELECT all with ordering
findAll(Pageable pageable) — SELECT with pagination
deleteById(id) — DELETE by primary key
delete(entity) — DELETE by entity
count() — COUNT(*)
existsById(id) — check if record exists
saveAll(Iterable<T>) — batch insert/update
flush() — synchronize changes to DB immediately

5.4 @Query Annotation — JPQL
When derived methods cannot express complex queries, use @Query with JPQL (Java Persistence Query Language). JPQL works on entity objects, not tables.
@Query("SELECT s FROM Student s WHERE s.email = :email")
Student findByEmail(@Param("email") String email);

// Named parameters
@Query("SELECT s FROM Student s WHERE s.age > :minAge AND s.city = :city")
List<Student> findStudentsByCriteria(@Param("minAge") int minAge,
                                     @Param("city") String city);

5.5 @Query — Native SQL
For database-specific SQL, use nativeQuery = true. Returns raw data (not entities by default).
@Query(value = "SELECT * FROM students WHERE email = ?1", nativeQuery = true)
Student findByEmailNative(String email);

5.6 @Modifying for UPDATE/DELETE Queries
@Modifying
@Transactional
@Query("UPDATE Student s SET s.email = :email WHERE s.id = :id")
int updateStudentEmail(@Param("email") String email, @Param("id") Long id);
@Modifying must always be paired with @Transactional when used for update/delete operations.
