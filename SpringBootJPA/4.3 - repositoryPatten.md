# Chapter 4: Repository Pattern in Spring Data JPA

## 4.3 Introduction

Spring Data JPA follows the **Repository Pattern**, which separates business logic from data access logic.

Instead of writing DAO classes and EntityManager code manually, Spring Data JPA provides Repository interfaces that automatically generate implementations at runtime.

### Without Spring Data JPA

```java
@Repository
public class StudentDao {

    @PersistenceContext
    private EntityManager entityManager;

    public Student save(Student student) {
        entityManager.persist(student);
        return student;
    }

    public Student findById(Long id) {
        return entityManager.find(Student.class, id);
    }
}
```

Lots of boilerplate code.

---

### With Spring Data JPA

```java
@Repository
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```

Spring automatically creates the implementation.

---

# 4.2 Repository Hierarchy

```text
Repository
      ↑
CrudRepository
      ↑
PagingAndSortingRepository
      ↑
JpaRepository
      ↑
JpaRepositoryImplementation
      ↑
SimpleJpaRepository
```

---

## Repository<T, ID>

Base marker interface.

```java
public interface Repository<T, ID> {
}
```

Contains no methods.

Purpose:

```text
Marks the interface as a Repository
```

---

## CrudRepository<T, ID>

Provides basic CRUD operations.

```java
public interface CrudRepository<T, ID>
```

Methods:

```java
save()

findById()

findAll()

delete()

deleteById()

existsById()

count()
```

---

## PagingAndSortingRepository<T, ID>

Extends CrudRepository.

Adds:

```java
findAll(Sort sort)

findAll(Pageable pageable)
```

Used for:

```text
Pagination
Sorting
```

---

## JpaRepository<T, ID>

Most commonly used repository.

```java
public interface JpaRepository<T, ID>
```

Extends:

```text
CrudRepository
+
PagingAndSortingRepository
```

Additional methods:

```java
flush()

saveAndFlush()

deleteAllInBatch()

deleteAllByIdInBatch()

getReferenceById()
```

---

## Interview Question

### Why use JpaRepository instead of CrudRepository?

Because JpaRepository already contains:

```text
CRUD Operations
Pagination
Sorting
Batch Processing
Flush Support
```

Hence most projects directly extend JpaRepository.

---

# 4.3 Creating a Repository

```java
@Repository
public interface StudentRepository

}
```

Spring Data JPA automatically generates the implementation at runtime.

# Common Methods Available

## save()

```java
studentRepository.save(student);
```

Used for:

```text
INSERT
UPDATE
```

Internal Logic:

```java
if(id == null)
    persist();
else
    merge();
```

---

## findById()

```java
Optional<Student> student =
        repository.findById(1L);
```

Returns:

```java
Optional<Student>
```

Why Optional?

```text
Record May Not Exist
Avoid NullPointerException
```

---

## findAll()

```java
List<Student> students =
        repository.findAll();
```

Fetches all records.

---

## deleteById()

```java
repository.deleteById(1L);
```

Deletes record using primary key.

---

## count()

```java
long total =
        repository.count();
```

Generated SQL:

```sql
SELECT COUNT(*)
FROM student;
```

---

## existsById()

```java
boolean exists =
        repository.existsById(1L);
```

Checks existence.

---

## saveAll()

```java
repository.saveAll(students);
```

Used for:

```text
Bulk Insert
Bulk Update
```

---

## flush()

```java
repository.flush();
```

Immediately synchronizes persistence context with database.

Normally Hibernate delays SQL execution until transaction commit.

flush() forces execution immediately.

# 4.4 Internal Working

When you write:

```java
public interface StudentRepository
extends JpaRepository<Student, Long> {
}
```

There is no implementation.

Spring creates one dynamically.

---

## Runtime Flow

```text
Application Startup
        ↓
Repository Scan
        ↓
Dynamic Proxy Created
        ↓
Proxy Delegates To
SimpleJpaRepository
        ↓
EntityManager
        ↓
Hibernate
        ↓
Database
```

---

## save() Flow

```text
repository.save(student)
        ↓
Proxy Object
        ↓
SimpleJpaRepository.save()
        ↓
EntityManager.persist()
or
EntityManager.merge()
        ↓
Hibernate
        ↓
SQL Generated
        ↓
Database
```

# 4.5 Query Derivation

One of Spring Data JPA's most powerful features.

Spring automatically generates queries by parsing method names.

---

## Example

```java

```

Generated Query:

```sql

FROM student
WHERE email = ?
```

# 4.6 JPQL Queries Using @Query

When method names become too complex, use @Query.

---

## What is JPQL?

JPQL = Java Persistence Query Language

Works with:

```text
Entities
Fields
Objects
```

NOT tables.

---

Example:

```java
@Query("""
SELECT s
FROM Student s
WHERE s.email = :email
""")
Student findByEmail(
    @Param("email") String email
);
```

---

## Multiple Parameters

```java
@Query("""
SELECT s
FROM Student s
WHERE s.age > :minAge
AND s.city = :city
""")
List<Student> findStudents(
        @Param("minAge") int minAge,
        @Param("city") String city
);
```

---

# 4.7 Native SQL Queries

Use database-specific SQL.

---

Example

```java
@Query(
value = """
SELECT *
FROM students
WHERE email = ?1
""",
nativeQuery = true
)
Student findByEmailNative(
        String email
);
```

---

## Difference Between JPQL and Native SQL

| JPQL                 | Native SQL        |
| -------------------- | ----------------- |
| Uses Entities        | Uses Tables       |
| Database Independent | Database Specific |
| Portable             | Less Portable     |
