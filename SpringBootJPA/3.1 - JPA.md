# Chapter 3: Java Persistence API (JPA)

# 3.1 Introduction to JPA

## What is JPA?

JPA stands for **Java Persistence API**.

It is a specification that defines how Java objects should be stored, retrieved, updated, and deleted from relational databases.

JPA provides a standard way to perform persistence operations in Java applications.

The word **Persistence** means storing data permanently in a database.

---

## Why JPA Was Introduced

Before JPA existed, developers used different ORM frameworks.

Examples:

* Hibernate
* TopLink
* OpenJPA
* EclipseLink

Each framework had its own APIs.

If a company wanted to switch from Hibernate to EclipseLink, large amounts of code had to be rewritten.

To solve this problem, Sun Microsystems introduced JPA.

JPA created a common standard that all ORM providers must follow.

---

## Advantages of JPA

### 1. Standardization

Provides a common programming model.

### 2. Portability

Can switch ORM providers easily.

### 3. Reduced Boilerplate Code

Less code compared to JDBC.

### 4. Better Maintainability

Applications become easier to maintain.

### 5. Database Independence

Works with multiple databases.

---

# 3.2 JPA is a Specification, Not an Implementation

This is the most important concept in JPA.

JPA only defines rules.

JPA itself contains:

* Interfaces
* Annotations
* Specifications

JPA does not contain implementation code.

Therefore, JPA cannot communicate with a database directly.

---

## Real World Example

Think about a driving license test.

The government defines rules.

But the government does not manufacture vehicles.

Similarly:

```text
JPA
  ↓
Rules

Hibernate
EclipseLink
OpenJPA
```

These frameworks implement the rules defined by JPA.

---

## JPA Providers

A JPA Provider is a framework that implements JPA.

Popular providers include:

* Hibernate
* EclipseLink
* OpenJPA

Most Spring Boot applications use Hibernate as the JPA provider.

---

## JPA vs Hibernate

| JPA                    | Hibernate                   |
| ---------------------- | --------------------------- |
| Specification          | Implementation              |
| Defines rules          | Implements rules            |
| Cannot work alone      | Can work independently      |
| Standard API           | ORM Framework               |
| Provided by Jakarta EE | Developed by Hibernate Team |

---

## Important Interview Statement

```text
JPA = Specification (Rules)

Hibernate = Implementation (Actual Framework)
```

---

## Architecture

```text
Application

      ↓

JPA Specification

      ↓

Hibernate

      ↓

JDBC

      ↓

Database
```

### Explanation

**Application**

Contains business logic written by developers.

↓

**JPA Specification**

Provides standard interfaces and annotations.

↓

**Hibernate**

Implements JPA and performs actual ORM operations.

↓

**JDBC**

Used internally by Hibernate to communicate with the database.

↓

**Database**

Stores the application data.

---

## Why Can't We Use JPA Alone?

JPA only defines rules.

Example:

JPA says:

```text
There must be:

- Entity Classes
- CRUD Operations
- EntityManager
- Transactions
```

But JPA does not provide the code that performs these operations.

Therefore we need an implementation such as Hibernate.

# Frequently Asked Interview Questions

## What is JPA?

JPA (Java Persistence API) is a specification that defines standards for ORM and persistence operations in Java applications.

---

## Is JPA a Framework?

No.

JPA is a specification.

Hibernate is a framework that implements JPA.

---

## Can JPA Work Without Hibernate?

No.

JPA requires an implementation such as Hibernate, EclipseLink, or OpenJPA.

---

## What is a JPA Provider?

A framework that implements JPA specifications.

Examples:

* Hibernate
* EclipseLink
* OpenJPA

---

## Which JPA Provider is Most Popular?

Hibernate is the most widely used JPA provider.

---

## What is the Difference Between JPA and Hibernate?

JPA defines the rules.

Hibernate implements those rules and performs actual database operations.
